# Glossary

| Term | Plain English |
|---|---|
| **Wearable** | A quarter-sized disc worn by the guest. It identifies them, opens the cabin door, pays for things and lets the ship recognise them. |
| **Guest app** | The guest's digital companion, available on phones, the web, stateroom TVs and kiosks. The *crew app* is the crew's version. |
| **Commerce platform** | The engine for buying and selling: catalog, cart, orders, pricing, promotions, tax and tips. |
| **E-commerce implementation** | Building that engine end to end, not just designing screens. |
| **Elastic Path** | A commercial e-commerce product used as the commerce engine. |
| **CrunchTime** | A restaurant and inventory management product used to track food, retail, housekeeping and boutique stock. |
| **Folio** | The guest's single running bill for the whole voyage. |
| **Entitlements** | What a guest has already paid for or is allowed to use, such as a drinks package or a spa booking. |
| **Gratuity** | The tip. |
| **Event bus** | A shared "announcement board": a system posts "order placed" and any system that cares picks it up. |
| **Microservices** | Small, independent software services, each doing one job, instead of one giant program. |
| **Integration** | Making two systems talk to each other. |
| **Backlog** | The prioritised list of features still to be built. |
| **Sprint** | A fixed two-week window in which the team builds and delivers a slice of the backlog. |
| **Product Owner** | The person who decides what gets built and in what order. |
| **BRD** | Business Requirements Document: the agreed description of *what* the product must do, not *how*. |
